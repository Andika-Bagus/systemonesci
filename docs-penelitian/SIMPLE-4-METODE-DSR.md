# 🔬 POIN 4: METODE DSR ITM SCI

## 🎯 APA ITU DSR?

### Design Science Research = Metodologi Penelitian untuk:
- **Bikin solusi nyata** (bukan cuma teori)
- **Solve problem bisnis** yang real
- **Test effectiveness** dengan data
- **Contribute knowledge** untuk akademik + industri

### Kenapa DSR untuk ITM SCI?
- ✅ **Ada masalah real:** PT Syntax monitoring manual 4 jam/hari
- ✅ **Bikin solusi:** ITM SCI system yang working
- ✅ **Ukur hasil:** 87.5% efficiency improvement
- ✅ **Akademik + bisnis:** Thesis + practical value

## 🔄 6 LANGKAH DSR (PEFFERS MODEL)

### 1️⃣ PROBLEM IDENTIFICATION (Minggu 1-2)
**Yang Dilakukan:**
- Interview IT team PT Syntax (7 orang)
- Interview management (2 orang)  
- Observasi proses monitoring manual
- Hitung cost inefficiency saat ini

**Output:**
- Problem statement yang clear
- Current state analysis (4 jam/hari monitoring)
- Business case justification (Rp 75+ juta savings potential)

### 2️⃣ DEFINE OBJECTIVES (Minggu 3-4)
**Yang Dilakukan:**
- Set target spesifik: 87.5% time reduction
- Define success metrics yang measurable
- Stakeholder alignment meeting
- Requirements gathering detailed

**Output:**
- SMART objectives (Specific, Measurable, Achievable, Relevant, Time-bound)
- Success criteria definition
- Project charter dengan scope clear

### 3️⃣ DESIGN & DEVELOPMENT (Minggu 5-14)
**Yang Dilakukan:**
```
Week 5: Architecture design (Laravel + React + MySQL)
Week 6-7: Core modules (Website + OJS management)
Week 8-9: Security (Authentication + encryption)
Week 10-11: Monitoring (Domain + PageSpeed + uptime)
Week 12-13: Dashboard + notifications
Week 14: Integration testing + bug fixes
```

**Output:**
- Working ITM SCI system
- 9 core modules implemented
- Security dengan AES-256 encryption
- Third-party API integration

### 4️⃣ DEMONSTRATION (Minggu 15)
**Yang Dilakukan:**
- Demo ke IT team (daily workflow)
- Demo ke management (executive dashboard)
- Demo security features (OJS Secure)
- Stakeholder feedback collection

**Output:**
- Demo scenarios completed
- Stakeholder feedback documented
- System validation dari users
- Issues list untuk final fixes

### 5️⃣ EVALUATION (Minggu 16-17)
**Yang Dilakukan:**
- **Performance testing:** Load time, response time, concurrent users
- **User testing:** TAM survey + SUS scale + satisfaction
- **Efficiency measurement:** Before/after time comparison
- **Business impact:** ROI calculation + KPI achievement

**Output:**
- Comprehensive evaluation report
- TAM score >4.0/5.0 (target)
- 87.5% efficiency improvement (proven)
- User satisfaction >4.0/5.0

### 6️⃣ COMMUNICATION (Minggu 18)
**Yang Dilakukan:**
- Thesis writing + documentation
- Results presentation ke stakeholders
- Knowledge sharing preparation
- Academic defense preparation

**Output:**
- Complete thesis document
- Stakeholder reports
- Academic presentation materials
- Best practices documentation

### Qualitative Evaluation:
- **TAM Survey:** Technology Acceptance Model questionnaire
- **SUS Scale:** System Usability Scale assessment  
- **User interviews:** Detailed feedback dari IT team
- **Satisfaction survey:** Overall experience rating
